# Code / data map — first pass (issue #002, 2026-11-09)

Source: `disasm/rop.s`, generated by `tools/disassemble.py` (Capstone m68k,
linear sweep from `0x200`). Regenerate with:

```
tools/.venv/bin/python tools/disassemble.py rop-original.gen disasm/rop.s
```

Output: **273,209 instructions, 196,448 undecodable bytes, 20 MB**.
ROM hash in the file header: MD5 `30c18fdbe2183f64702ae9f1a45d63f9`.

## How to read this map

Confidence levels: **verified** = reached from a vector or from code that
is itself vector-reached, and the bytes decode as sensible 68000;
**likely** = strong indirect evidence (strings, entropy, calls into it);
**provisional** = best guess from entropy/strings, needs Ghidra's recursive
analysis (#003) to confirm.

**Warning about the method:** a linear sweep decodes data as plausible
m68k almost everywhere — per-16 KB "instruction density" came out
0.70–1.00 across the whole ROM, including regions that are certainly
graphics/text. Density is therefore **not** evidence of code. Only the
ranges below marked verified/likely should be treated as code.

## Vectors (0x000–0x0FF) — verified

Only three non-zero vectors in the whole table; everything else is
`0x00000000` (a bus/address/illegal/trap fault would jump to address 0):

| Vector | Address | Target | Notes |
|---|---|---|---|
| 0 SSP | `0x000` | `0x00FFEC1E` | Initial stack pointer (top of 64 KB RAM, minus 0x1E) |
| 1 reset | `0x004` | `0x00000200` | Entry point |
| 28 level 4 (HBlank) | `0x070` | `0x00001270` | Single instruction: `rte` — empty handler |
| 30 level 6 (VBlank) | `0x078` | `0x00001272` | Real handler (see below) |

## Entry code (0x200–0x2FF) — verified, annotated

Standard Sega startup, then the game's own init:

- `0x200` `tst.l $A10008` / `tst.w $A1000C` — TMSS hardware check; if the
  version register reads back, skip the "SEGA" write.
- `0x226` `move.l #$53454741 ("SEGA"), $A14000` — the TMSS trademark
  write; without it the console shows the red "produced by or under
  license" screen and halts.
- `0x210` `lea $28E(pc),a5` + loops at `0x238` — VDP register init: 24
  register values read from the data table at `0x28E` (first words
  `0x8000/0x8134/0x8230/...`) and written to the VDP control port
  `$C00004` (a4). This is also why the linear sweep first "fails" here:
  the table at `0x28E` is data, not code.
- `0x23E`–`0x282` — clear RAM (loop at `0x25C` writes zeros via a6=0 as
  a pointer into `0xFF0000`…), clear VRAM/CRAM, Z80 bus request/release
  at `$A11100`, TMSS region check at `$A10001`.
- `0x28C` `bra $2FA` — jumps over the VDP table.
- `0x2FA` `tst.w $C00004` then `jsr $FD07C` — the **runtime checksum
  self-test** (see below), then `nop`, `move.w #$2700,sr`.
- `0x30C` `jsr $4323C` — first game routine (save/SRAM validation:
  clears `$FF0168`, calls `$42FC8` and `$DCE2`, compares a byte to
  `$E0`; details are issue #003/#007 work).
- `0x318`–`0x32C` — wait for VBlank bit, `move.w #$8134,$C00004`
  (display on), `bsr $3AA` (joypad read), `bsr $A14` (RAM clear +
  VDP register setup), `bsr $3AA` again.

Subroutines reached from entry (verified real code):

- `0x3AA` — joypad read: writes `$40/$00` to `$A10003` with delay
  loops, reads `$A10003`, returns the byte in d0/d1. The VBlank
  handler at `0x1272` inlines the same sequence.
- `0xA14` — clears work RAM (`0xFF0000`+, `0x3FF6` longwords) then
  writes a VDP register set (`$8004, $8134, $8228, $8330, …`).
- `0x1272` VBlank handler — `move.w #0,$FF0016` (clear vblank flag),
  `addq.l #1,$FF0010` (frame counter++), saves d0-d2/a0, Z80 bus
  request, joypad read from `$A10003` (d0 = buttons, shifted/masked),
  then continues past `0x12D0` (rest is issue #003).

## Runtime checksum self-test (0xFD07C–0xFD0CB) — verified

The game's own anti-tamper check, called from entry before anything
else. Found and **verified by simulation** (Python re-implementation
of the loop reproduces the constant exactly):

```
0xFD07C  moveq #0,d0 ; suba.l a0,a0 ; move.l #$3F41F,d1
0xFD086  cmpa.w #$18C,a0 ; bne $FD090 ; addq.w #4,a0 ; bra $FD092
0xFD090  add.l (a0)+,d0
0xFD092  subq.l #1,d1 ; bgt $FD086
0xFD096  cmpi.l #$8F33608C,d0 ; bne $FD0A0 ; rts
```

- Sums 32-bit big-endian words from `0x000000` to `0xFD07B`, skipping
  the longword at `0x18C` (which contains the header checksum), over
  `0x3F41F` iterations. Expected sum: **`0x8F33608C`**.
- On mismatch: `0xFD0A0` sets VDP registers, fills VRAM with `$000E`,
  then `0xFD0CA bra $FD0CA` — an **infinite loop**. The game hangs at
  boot with a blank screen; interrupts are masked (`SR=$2700`).
- Consequence for modding: fixing only the header checksum is **not
  enough**. Every mod must also patch the `cmpi.l` immediate at
  `0xFD098` to the new sum. That immediate sits past the summed range,
  so patching it does not change the sum. `tools/checksum.py fix-all`
  does both, in that order (proven — see `docs/toolchain.md`).

## Text locations (for issue #004)

- **Main dialogue blob:** `0x0D6EBA–0x0DC0C0` (20,998 bytes). Starts
  mid-word (`Anunknownbuilding ASorcerer'sGuildYoufeeleyeswatchingyou…`).
  Words are concatenated — the game must insert spaces/line breaks from
  a control stream or dictionary. Do not treat it as plain sentences.
- **Spaced UI/message strings** (normal ASCII, `0x00`-terminated,
  embedded in code): `0x01215A` (Void death message), `0x015BB8`
  (`Continue`/`Start`/menu words), `0x023934` (debug format
  `N^NuSp:%i Dir:%i Ac:%i St:%i Dr:%i`), `0x02752A` (`Help Off`,
  `Diags On/Off`), `0x02937D–0x029767` (XP/gold/shop/spell-effect
  messages, e.g. `Sorry you don't have enough gold to buy that.`).
  Total spaced strings ≥8 chars in ROM: 440 (raw `strings` count 1,807
  is inflated by tile data).
- **Story/credits fragments, strided:** `0x0A66F4` (`The Book of
  Nexus…`), `0x0B3D4E`, `0x0B6226` (`Rings of Power — A Fantasy
  Adventure`, `Naughty Dog, Inc`, staff names). Text appears in ~8-char
  chunks separated by non-printable bytes — stored interleaved or
  compressed; needs #004 analysis, not a plain strings dump.
- **Credits block:** `0x1B324` (`LICENSED BY SEGA ENTERPRISES LTD.`,
  `A NAUGHTY DOG INC. PRODUCTION`, design/programming/art/music
  lines). The exact string `Rings of Power` does not occur anywhere in
  the ROM as contiguous ASCII — the title-screen text is in the
  strided/interleaved format above.

## Open questions (for #003)

1. Where does real code end? The `0x010000–0x043FFF` block looks like
   code, but the boundary with the `0x044000` compressed block and the
   `0x0E0000–0x0FBFFF` mixed block needs recursive disassembly.
2. What do `$42FC8`, `$DCE2`, `$43012` (called from `$4323C`) do?
   `$4323C` smells like SRAM/save validation.
3. Is the `0x044000` / `0x094000` high-entropy data one compression
   format (Nemesis/Kosinski/Enigma — the usual Genesis codecs), and
   which block is graphics vs maps?
4. How is the dialogue blob tokenised — where are the word boundaries
   and control codes?
