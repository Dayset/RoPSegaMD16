# Code / data map — first pass (issue #002, 2026-11-09)

Source: `disasm/rop.s`, generated by `tools/disassemble.py` (Capstone m68k,
linear sweep from `0x200`). Regenerate with:

```
tools/.venv/bin/python tools/disassemble.py rop-original.gen disasm/rop.s
```

Output: **273,209 instructions, 196,448 undecodable bytes, 20 MB**.
ROM hash in the file header: MD5 `30c18fdbe2183f64702ae9f1a45d63f9`.

## How to read this map

Confidence levels: **verified** = reached from a vector or from code that
is itself vector-reached, and the bytes decode as sensible 68000;
**likely** = strong indirect evidence (strings, entropy, calls into it);
**provisional** = best guess from entropy/strings, needs Ghidra's recursive
analysis (#011) to confirm. After #011, the two target ranges
(`0x010000–0x043FFF`, `0x0E0000–0x0FBFFF`) are decided per function —
see "Ghidra recursive analysis (issue #011)" below.

**Warning about the method:** a linear sweep decodes data as plausible
m68k almost everywhere — per-16 KB "instruction density" came out
0.70–1.00 across the whole ROM, including regions that are certainly
graphics/text. Density is therefore **not** evidence of code. Only the
ranges below marked verified/likely should be treated as code.

## Vectors (0x000–0x0FF) — verified

Only three non-zero vectors in the whole table; everything else is
`0x00000000` (a bus/address/illegal/trap fault would jump to address 0):

| Vector | Address | Target | Notes |
|---|---|---|---|
| 0 SSP | `0x000` | `0x00FFEC1E` | Initial stack pointer (top of 64 KB RAM, minus 0x1E) |
| 1 reset | `0x004` | `0x00000200` | Entry point |
| 28 level 4 (HBlank) | `0x070` | `0x00001270` | Single instruction: `rte` — empty handler |
| 30 level 6 (VBlank) | `0x078` | `0x00001272` | Real handler (see below) |

## Entry code (0x200–0x2FF) — verified, annotated

Standard Sega startup, then the game's own init:

- `0x200` `tst.l $A10008` / `tst.w $A1000C` — TMSS hardware check; if the
  version register reads back, skip the "SEGA" write.
- `0x226` `move.l #$53454741 ("SEGA"), $A14000` — the TMSS trademark
  write; without it the console shows the red "produced by or under
  license" screen and halts.
- `0x210` `lea $28E(pc),a5` + loops at `0x238` — VDP register init: 24
  register values read from the data table at `0x28E` (first words
  `0x8000/0x8134/0x8230/...`) and written to the VDP control port
  `$C00004` (a4). This is also why the linear sweep first "fails" here:
  the table at `0x28E` is data, not code.
- `0x23E`–`0x282` — clear RAM (loop at `0x25C` writes zeros via a6=0 as
  a pointer into `0xFF0000`…), clear VRAM/CRAM, Z80 bus request/release
  at `$A11100`, TMSS region check at `$A10001`.
- `0x28C` `bra $2FA` — jumps over the VDP table.
- `0x2FA` `tst.w $C00004` then `jsr $FD07C` — the **runtime checksum
  self-test** (see below), then `nop`, `move.w #$2700,sr`.
- `0x30C` `jsr $4323C` — serial-EEPROM / save validation (issue #003,
  call-graph level): calls `$42FC8` (EEPROM enable/init) and `$DCE2`
  (joypad port 2 read), compares a byte to `$E0` (B+C+Start held on
  pad 2 — a hidden combo that forces a blank save); otherwise validates
  the 128-byte buffer at `$FF016A` by byte-sum. Reads via `$43012`,
  writes via `$430F4` (CORRECTED in #021 — this file had them swapped
  before #011); both bit-bang a Microwire-style serial EEPROM
  through `$200000` (DI=D0, CLK=D6, DO=D7). Full analysis is #019.
- `0x318`–`0x32C` — wait for VBlank bit, `move.w #$8134,$C00004`
  (display still blank, V-int + DMA on), `bsr $3AA` (joypad read),
  `bsr $A14` (RAM clear + VDP register setup), `bsr $3AA` again,
  wait for DMA-busy bit 1 to clear, `move.w #$8174,$C00004`
  (**display ON**).
- `0x35C`–`0x390` — title/attract loop: wait VBlank, read joypad,
  exit if a button is pressed, else call `$4E6` (H-scroll attract
  animation via VRAM `$2000`) when `$FFC000==0`; then `bra $119E`.
- `0x119E` — main init: restore SSP `$FFEC1E`, clear 64 KB RAM, copy
  `$240` bytes ROM `$FCE3C` → RAM `$FF0000`, write `"MANX"` at
  `$FFC422`, `jsr $EB806` (sound-driver upload), `SR=$2000`,
  `jmp $D25C`.
- `0xD25C` — game-code dispatcher: calls `$11E06`, `$14FB6`,
  `$1B5D6`, `$32D0E`, `$173BC`, `$D28E`, `$179B6`; its `rts` at
  `0xD28C` is not reached in normal flow. `$D28E` (1,876 bytes) is the
  flag-driven dispatcher (calls `$1350` queue-pop, `$12B82`,
  `$12FE8`, branches to `$D8BA` — 52-byte structs at `$FF02B4` /
  `$FF02DB`); the main loop itself is #020's work.

Subroutines reached from entry (verified real code):

- `0x3AA` — joypad read: writes `$40/$00` to `$A10003`/`$A10005`
  with delay loops, reads **both** ports — port 1 → `$FFC00E`,
  port 2 → `$FFC010` — returns the port-1 byte in d0 (port 2 in d1).
  The VBlank handler at `0x1272` inlines only the port-1 half.
- `0xA14` — clears work RAM (`0xFF0000`+, `0x3FF6` longwords) then
  writes a VDP register set (`$8004, $8134, $8228, $8330, …`).
- `0x1272` VBlank handler — `move.w #0,$FF0016` (clear vblank flag),
  `addq.l #1,$FF0010` (frame counter++), saves d0-d2/a0, Z80 bus
  request, joypad read from `$A10003` (d0 = buttons, shifted/masked),
  `jsr $EB772` (sound tick), then the debounce/queue logic past
  `0x12D0`: changed byte → `$FF0018=d0`, `$FF0019=3`, `rte`
  (`0x1312`); unchanged → `$FF0019--`, re-queue into the 16-entry
  ring `$FF001C`[head `$FF001A`] every 3 frames unless full (head+1 &
  `$F` == tail `$FF001B`), `rte` (`0x1340`/`0x134E`). `$1350` is the
  separate polled pop routine (called from `$D28E`).
- `0x1270` HBlank handler — single `rte`; never fires (boot R0=`$04`
  leaves H-int enable bit 4 = 0; BlastEm log: 0 hits in 10 s).
- `0xEB772` — per-frame **sound/music tick** (NOT a graphics dispatch
  — corrects the line in `docs/overview.md`): PAL/NTSC tempo tick
  written to Z80 RAM `$A000E6`, `jsr $EBAC6` (sound command queue),
  every 16 frames `jsr $EBA00` (music streamer). Called only from
  VBlank (`0x12F2`).
- `0xEB806` — sound-driver upload: `$1576` bytes ROM `$EBB6E` →
  Z80 RAM `$A00000`; sets PAL flag `$FF0222` from `$A10001` bit 6.
  Called from `$119E`, `$EB88A` (start-song), `0xEBB10`.

## Runtime checksum self-test (0xFD07C–0xFD0CB) — verified

The game's own anti-tamper check, called from entry before anything
else. Found and **verified by simulation** (Python re-implementation
of the loop reproduces the constant exactly):

```
0xFD07C  moveq #0,d0 ; suba.l a0,a0 ; move.l #$3F41F,d1
0xFD086  cmpa.w #$18C,a0 ; bne $FD090 ; addq.w #4,a0 ; bra $FD092
0xFD090  add.l (a0)+,d0
0xFD092  subq.l #1,d1 ; bgt $FD086
0xFD096  cmpi.l #$8F33608C,d0 ; bne $FD0A0 ; rts
```

- Sums 32-bit big-endian words from `0x000000` to `0xFD07B`, skipping
  the longword at `0x18C` (which contains the header checksum), over
  `0x3F41F` iterations. Expected sum: **`0x8F33608C`**.
- On mismatch: `0xFD0A0` sets VDP registers, fills VRAM with `$000E`,
  then `0xFD0CA bra $FD0CA` — an **infinite loop**. The game hangs at
  boot with a blank screen; interrupts are masked (`SR=$2700`).
- Consequence for modding: fixing only the header checksum is **not
  enough**. Every mod must also patch the `cmpi.l` immediate at
  `0xFD098` to the new sum. That immediate sits past the summed range,
  so patching it does not change the sum. `tools/checksum.py fix-all`
  does both, in that order (proven — see `docs/toolchain.md`).

## Ghidra recursive analysis (issue #011, 2026-11-09)

Ghidra 11.4.2, full auto-analysis re-run on the project in
`tools/ghidra/projects/rop`. Exports under `disasm/ghidra/`
(`functions.txt`, `call_edges.txt`, `function_bodies.txt`,
`call_trees.txt`, `not_reachable_from_entry.txt`, `README.md` —
the README carries the full gap inventory, the missed-code list, and
the cross-check method; this section is the summary).

- **446 functions, 1,449 direct call edges.** Auto-analysis found
  435; **11 were created manually** — the analyser only follows
  direct calls and vector targets, so code reached only via computed
  dispatch (jump tables, `$2BBD2` dispatch, function pointers) or
  with no callers at all is invisible to it: `0x1270` (HBlank, 2 B),
  `0x1272` (VBlank, 216 B), `$EB772` (86 B), `$EBA00` (music streamer,
  126 B — the `jsr $EBA00` at `0xEB7BE` was in Ghidra's listing but
  the analyser never followed it to create the callee), `$EB7C8`
  (stop-sound, 62 B, dead code), `$EB8E0` (18 B), `$2B2B2` and
  `$2B502` (combatant-setup wrappers, 336 B / 242 B), `$2988E`
  (68 B), `$3536C` (46 B), `$3539A` (266 B). Three more code blocks
  were disassembled but are **not** function entries (jump-table
  case bodies, no `link` prologue): `$1E022`'s blocks at
  `0x1E02E–0x1E075`, the spell-area block at `0x38850–0x38889`,
  the sound-cluster blocks at `0xEB9A0–0xEB9C3`.
- **Coverage (exact body addresses, not spans):**
  `0x010000–0x043FFF` 90.7% (193,264/212,992 B),
  `0x0E0000–0x0FBFFF` 0.9% (984 B, the sound cluster only),
  `0x000000–0x00FFFF` 10.5%, `0x0FC000–0x0FFFFF` 0.5%,
  all other ranges 0.0% — which independently confirms the #005/#006
  data classifications for the compressed blocks.
- **Every gap ≥64 B in the two target ranges is classified** with
  function-address evidence (data references = literal immediates in
  real code; call targets = direct `jsr`/`bsr`/`jmp`/`bra` targets):
  `0x010000–0x043FFF` has 16 gaps — 15 data (menu/message strings,
  the 7,718 B string/table block at `0x0197B0`, the terrain-decoder
  tables at `0x0433C0`, three combat word tables at `0x3A220`/
  `0x3A354`/`0x3A5D0`, the Void string at `0x01215E`) and 1 code
  (the `$1E022` case blocks); `0x0E0000–0x0FBFFF` has 2 gaps —
  `0x0E0000–0x0EB771` (structured table data; one interior address
  `0xE0A18` pushed as a pointer at `0x32EBE`) and
  `0x0EBB6E–0x0FBFFF` (Z80 driver blob `0xEBB6E–0xED0E4` + rest).
- **Cross-check:** all 289 distinct absolute-`jsr` targets in the
  linear sweep (3,143 sites) are function entries, and all 289
  appear among Ghidra's 413 distinct callees (1,449 edges, all
  entries); the one genuine missed target was `$EBA00`
  (`jsr $EBA00(pc)` at `0xEB7BE`, fixed). Where Ghidra and the
  linear sweep disagree, Ghidra wins — except for computed-dispatch
  code, where the Capstone decode + the #007/#008/#020/#021 traces
  are the evidence.
- **Call trees mapped** (`disasm/ghidra/call_trees.txt`): entry
  `0x200` reaches 405 functions (depth 1 is exactly the verified
  trace `$3AA`/`$4E6`/`$A14`/`$119E`/`$4323C`/`$FD07C`; depth 3 holds
  the seven `$D25C` callees, agreeing with #020); VBlank `0x1272`
  reaches 10 (`$EB772` → `$EBA00`/`$EBAC6`, agreeing with the
  verified sound-tick trace); `$4323C` reaches 14 (the four helpers
  `$DCE2`/`$42FC8`/`$43012`/`$430F4` plus `$42E34`/`$42E76`/`$42EBA`/
  `$42EEE`/`$42F96` and `$DCCA`/`$42F26`/`$42F5E`/`$42FD8`,
  agreeing with docs/architecture.md); `$EB772` reaches 9.
- **Ghidra limitations recorded:** it merges flow-connected routines
  into one function (`$2B240` inside `FUN_0002b190`, `$2B4B0`
  inside `FUN_0002b402`, `$35600` inside `FUN_000354a4`) and its
  bodies exclude embedded jump tables (correctly — they are data).
  41 functions are not reachable from entry by direct edges
  (vectors, sound cluster, computed dispatch) — listed in
  `disasm/ghidra/not_reachable_from_entry.txt`.

## Text locations (for issue #004)

- **Main dialogue blob:** `0x0D6EBA–0x0DC0C0` (20,998 bytes). Starts
  mid-word (`Anunknownbuilding ASorcerer'sGuildYoufeeleyeswatchingyou…`).
  Words are concatenated — the game must insert spaces/line breaks from
  a control stream or dictionary. Do not treat it as plain sentences.
- **Spaced UI/message strings** (normal ASCII, `0x00`-terminated,
  embedded in code): `0x01215A` (Void death message), `0x015BB8`
  (`Continue`/`Start`/menu words), `0x023934` (debug format
  `N^NuSp:%i Dir:%i Ac:%i St:%i Dr:%i`), `0x02752A` (`Help Off`,
  `Diags On/Off`), `0x02937D–0x029767` (XP/gold/shop/spell-effect
  messages, e.g. `Sorry you don't have enough gold to buy that.`).
  Total spaced strings ≥8 chars in ROM: 440 (raw `strings` count 1,807
  is inflated by tile data).
- **Story/credits fragments, strided:** `0x0A66F4` (`The Book of
  Nexus…`), `0x0B3D4E`, `0x0B6226` (`Rings of Power — A Fantasy
  Adventure`, `Naughty Dog, Inc`, staff names). Text appears in ~8-char
  chunks separated by non-printable bytes — stored interleaved or
  compressed; needs #004 analysis, not a plain strings dump.
- **Credits block:** `0x1B324` (`LICENSED BY SEGA ENTERPRISES LTD.`,
  `A NAUGHTY DOG INC. PRODUCTION`, design/programming/art/music
  lines). The exact string `Rings of Power` does not occur anywhere in
  the ROM as contiguous ASCII — the title-screen text is in the
  strided/interleaved format above.

## Open questions (for #003) — answered / partially answered 2026-11-09

1. Where does real code end? **Answered for the two #011 ranges.**
   Ghidra recursive analysis (446 functions, 1,449 call edges,
   exports under `disasm/ghidra/`): `0x010000–0x043FFF` is 90.7%
   code with every gap ≥64 B classified (15 data, 1 code — the
   `$1E022` case blocks); `0x0E0000–0x0FBFFF` is 0.9% code (sound
   cluster only) with both gaps classified as data; the compressed
   blocks have 0 functions. The interrupt-handler functions at
   `0x1270`/`0x1272` and `$EB772` were created manually (vector
   targets have no call sites). Remaining: the `$FF1EC0` bitmap
   consumers and the `$2B240`-family entry mechanism (computed
   dispatch — see #021).
2. What do `$42FC8`, `$DCE2`, `$43012` (called from `$4323C`) do?
   **Answered at call-graph level.** `$42FC8` = serial-EEPROM
   enable/init (8 clocked `$80` writes to `$200000` + `$42E76`);
   `$DCE2` = joypad port 2 read (shared utility, 8 call sites);
   `$43012` = EEPROM **read** (block; command out via `$42EBA` ×8
   with `or.w #1` in the command word — the read bit, ACK in via
   `$42F96`, retry limit 10 in `$FF014C`); `$430F4` = EEPROM
   **write** (one byte; same bit-bang pattern without the `or #1`).
   Together they bit-bang a Microwire-style serial EEPROM through
   `$200000` (DI=D0, CLK=D6, DO=D7); `$E0` = B+C+Start on pad 2,
   `$B0` = A+C+Start. BlastEm auto-detected a 128-byte EEPROM
   (all `$FF`). Chip identity, the `$FF016A` buffer layout, and the
   return-value semantics are #019's work.
3. Is the `0x044000` / `0x094000` high-entropy data one compression
   format (Nemesis/Kosinski/Enigma — the usual Genesis codecs), and
   which block is graphics vs maps?
4. How is the dialogue blob tokenised — where are the word boundaries
   and control codes?
