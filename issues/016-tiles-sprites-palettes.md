## Acceptance
- [x] ~~`0x060000–0x093FFF` decoded as 4-bpp tiles; first tileset rendered
      to PNG under `disasm/graphics/`~~ — **STALE, corrected:** that
      range is NOT raw tiles (proven #005/#011/#017; `disasm/map.md`
      corrected; the `$96120` streams start at `0x09638C`, and
      `0x068300–0x093FFF` is ~172 KB of unknown data). The real tiles
      are the `$DD5C` records in the `$96120` table (62 records) and
      the `$B86AE` table (90 records). Full tilesets rendered with
      correct palettes: `disasm/graphics/016_font_rec00_full.png`
      (rec 0, 103 tiles), `016_terrain_rec06_full.png` (rec 6, 438
      tiles), `016_portrait_b86ae_rec00_full.png` (rec 0, 36 tiles).
- [x] Palette(s) located in CRAM format and listed — master table ROM
      `0x0CC9D8`, **31 palettes (0–30)**; the next slot (`0x0CCDB8`,
      slot 31) is ASCII menu text: MAIN/Inven/Spells/Party/Search/
      Map/Camp/System/FIGHT/Flee — the table's boundary, confirming
      it ends there. Full list in `docs/graphics.md` §10.2. **Correction:** CRAM order is `r=(w>>1)&7, g=(w>>5)&7,
      b=(w>>9)&7` — #005/`render_tiles.py` had R and B swapped
      (proven by the minimal VDP test ROM: CRAM[1]=`0x0E00` displays
      blue). `render_tiles.py` fixed; #005 PNGs flagged for regen.
- [x] Sprite table format + at least one sprite decoded — attribute
      format verified #015 (§7.3); pattern side resolved here
      (`docs/graphics.md` §10.3): attract sprites (tiles 513–584) are
      **generated by `$AB2`** (0xAB6–0xB28, from byte table `$D92`,
      CPU-copied to VRAM `$4020`), NOT `$DD5C` records — the issue's
      premise was half wrong. `$B86AE` records ARE the `$DD5C`
      sprite-pattern sets (`[32-byte palette][36 tiles]`); rec 0
      rendered as `016_portrait_b86ae_rec00_full.png`.
- [x] Tile data confirmed as tiles (not misread code/text) — full
      tilesets render coherently only packed (§10.4); no
      `$96120`/`$B86AE` record renders as noise under packed.
      **Headline: the packed-vs-planar paradox is RESOLVED**
      (`docs/graphics.md` §10.1) — the bytes are packed, the upload
      path is verbatim, and a minimal VDP test ROM proves the VDP
      consumes them as packed (tile 93: 64/64 pixels). The textbook
      "bitplanar" claim is flagged for re-verification, not settled.
